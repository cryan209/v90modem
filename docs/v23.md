# V.23 1200/75

`AT+MS=V23C` (alias `V23`) or `--mode v23c` selects V.23 with a constant
carrier and asymmetric FDM (V.250 Table 13). It runs two channels at once:

- **Forward channel:** mode 2 (§2), 1200 bit/s, 1300 Hz mark and 2100 Hz space.
- **Backward channel:** §4, 75 bit/s, 390 Hz mark and 450 Hz space.

Both are SpanDSP FSK presets (`FSK_V23CH1`/`CH2`), on the same engine path as
V.21 and Bell 103 (`docs/v21.md`). There is no V.8, so both ends must be set
alike. Mode 1 (600 bit/s) and the switched-carrier, half-duplex form (`V23S`)
are not offered.

## Who sends 1200

V.23 does not tie a direction to a role. V.250 6.4.1 says the distinct
receive bounds of `+MS` "select either direction for asymmetric modulations
like ITU-T Rec. V.23 with constant carrier":

| Command | We send | We receive |
|---|---|---|
| `AT+MS=V23C,0,1200,1200,75,75` | 1200 | 75 |
| `AT+MS=V23C,0,75,75,1200,1200` | 75 | 1200 |
| `AT+MS=V23C,0,75,75` (no receive bounds, so they copy these) | 75 | 1200 |
| `AT+MS=V23C` | answerer 1200, caller 75 | |

The default is the videotex arrangement: the terminal calls and keys at
75 bit/s, and the host answers with pages at 1200. Bounds that allow neither
direction are ERROR.

- **CONNECT** carries the rate the DTE receives at, so the terminal sees
  `CONNECT 1200`.
- **+MCR, ATI6 and the GUI** report both directions, e.g. `Rate TX 75 RX 1200`.
- The **V.14 rate** is the transmit rate.

## Carrier detect

V.23 §8.3.2 Table 3 gives circuit 109 the same 300-700 ms OFF-to-ON during
call establishment as V.21. CONNECT therefore uses the same qualification:
the receive channel's mark (1300 or 390 Hz) must hold at least half of the
received power for 400 ms. Mark alone matters here: 2100 Hz is the forward
channel's space, so mark-and-space qualification once took V.8's answer tone
for V.23 carrier (`docs/legacy_automode.md`). A calling V.23 modem holds its
transmitter until the answer tone has ended (V.25 3.10).

Two modems that both send 1200 never connect, since neither hears the 75 bit/s
channel. Neither does V.23 against V.21.

## Tests

- **`engine_pair_test`, both laws.** Default direction (graded with ATI6),
  the bounds-reversed direction, and a two-senders-of-1200 no-connect case.
  `--payload-lines 2` keeps the 75 bit/s direction to about 14 s of line time.
- **`tools/gui_loopback_test.py v23`.** Binary payload echoed byte-exact over
  local SIP: 280 bytes up at 75 bit/s, then back at 1200.
- **`at_ms_test`.** Bounds parsing and the offer each one selects.

Not done: the backward channel's own circuits (118-122), echo protection
(Table 3 Note 2's 200-275 ms), and any real V.23 or Minitel modem.
