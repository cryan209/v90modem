# V.44 modem stream support

V.44 is available in the C modem data stack. It is selected explicitly:

```sh
ME_DATA_FRAMING=lapm ME_DATA_COMPRESSION=v44 ./sip_v90_modem <usual SIP arguments>
```

`ME_DATA_COMPRESSION=v42bis` (or unset) uses the existing V.42bis offer;
`ME_DATA_COMPRESSION=none` uses plain LAPM. These choices apply to LAPM framing.
V.44 currently offers both directions with 512 codewords, 32-byte strings and
1024-byte history per direction. A peer that does not agree to V.44 uses plain
LAPM. Selecting V.44 does not silently select a second compression algorithm.

`ds_init_v44()` accepts explicit local TX/RX parameter proposals. The public
`v42_set_v44()` API configures the Annex A offer before `v42_restart()`; bare
V.42 callers must attach their own codecs when they enable compression.

## Implementation

The streaming encoder and decoder in `v44.c` were ported from
`modem-dsp-emu/tools/v44.py`. Production has no Python dependency. The encoder
retains the reference's append-only string-segment policy and compressed-mode
operation; it does not emit string extensions or implement adaptive switching
to transparent mode. The decoder accepts string extensions, including overlapping
history copies, and compressed/transparent mode changes. Packet methods and
post-link Parameter Mode negotiation are not supported or advertised.

The implementation uses ITU-T V.44 (11/2000) and Corrigendum 1 (03/2002):

- 6.4/6.6: dictionary decoding, extension lengths, prefixes and bit order.
- 7.5: initial compressed mode, six-bit codewords and seven-bit ordinals.
- 7.11/7.12: ordinal/codeword STEPUP and dictionary/history REINIT.
- 7.13: FLUSH aligns the stream without clearing dictionaries.
- 7.4 and Annex A: sender-relative TX/RX parameters and complementary directions.
- Corr.1, 7.4.1: XID parameter defaults and C0.N=0 when Parameter Mode is unsupported.

GI=FF is parsed as an XID user-data subfield with no group-length bytes. V.44
replies contain one compression algorithm, with agreed local directions and the
smaller complementary TX/RX limits. Omitted parameters use Table 10 defaults,
including history size three times the proposed codeword count. C0.N=0 allows
XID negotiation with peers that advertise Parameter Mode support.

Encoded bytes enter LAPM once; retries reuse the stored encoded information
frame. A physical retrain or line-rate change preserving LAPM also preserves
codec context. A new LAPM session initializes fresh dictionaries. Invalid codewords,
lengths or histories report a link error, without substituting output bytes.

## Verification

```sh
make v44_test data_stack_test v42_link_test sip_v90_modem v90_engine_replay
./v44_test
./data_stack_test
./v42_link_test
cc -std=c99 -fPIC -shared v44.c -o /tmp/libv44.so  # .dylib also works on macOS
python3 tools/v44_interop.py --reference ../modem-dsp-emu --library /tmp/libv44.so
```

The independent C/Python check passes 27 cases, including exact encoder-wire
matches and byte-at-a-time decoding. Native tests cover all 253 extension
lengths, dictionary/history reinitialization, malformed streams and the captured
CX93001 message (`cx-v44-`, 512 `A` bytes, CR/LF). Integration tests cover
asymmetric limits, either direction alone, refusal/fallback, corrupted-frame
retries, idle/rate changes and reconnects. Independent HDLC tests check Annex A
wire encoding, the captured CX93001 XID, invalid limits and omitted-parameter
defaults. Linux ASan/UBSan, native macOS UBSan, V.42bis cross-codec checks and
PCM modem loopbacks pass.

Porting exposed a reference-decoder bug: V.44 7.11.2(d) permits multiple STEPUP
controls before a codeword that needs more than one extra bit. Both the C port
and Python reference now handle that sequence; the Python regression suite passes
13 tests.

These results establish codec and LAPM interoperability against independent code
and preserved hardware bytes. A new live V.44 hardware call has not been verified.
The earlier RasFinder application-dictionary problem is not resolved by this port.
